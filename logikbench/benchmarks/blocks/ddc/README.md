# ddc (digital down converter)

## What it is

A synthesizable, parameterizable **Digital Down Converter (DDC)**. It takes a
real bandpass input stream, mixes a selected band down to complex baseband with
a numerically controlled oscillator (NCO), decimates with a multiplierless CIC
filter, and flattens the residual passband droop with a compensation FIR,
producing a decimated complex **I/Q** stream.

```
              NCO (cos/sin)
                  |
  x[n] --+--> (* cos) --> I --> CIC(/R) --> FIR --> iout   (Fs/R rate)
         |
         +--> (*-sin) --> Q --> CIC(/R) --> FIR --> qout   (Fs/R rate)
```

## Architecture

1. **NCO** (`ddc_nco`, generated by `genddc.py`): a `PAW`-bit phase accumulator
   advances by a runtime tuning word `ftw` on each valid input sample. The top
   `AW` phase bits address a shared `NSIN`-entry sine ROM. The cosine output
   reuses the same ROM by adding a quarter table (`NSIN/4`) to the index, so
   `cos(phase) = sin(phase + 90deg)` -- the same trick used by `blocks/fft`'s
   twiddle ROM. Generated frequency: `f_nco = ftw * Fs / 2^PAW`.

2. **Mixer** (`ddc_mixer`): two signed `DW x SW` multiplies producing
   `I = x*cos`, `Q = x*(-sin)`; each product is round-half-up and symmetrically
   saturated back to a Q1.15 working sample.

3. **CIC decimator** (`ddc_cic`, Hogenauer): `STAGES` integrators at the high
   (input) rate, decimation by `R`, then `STAGES` comb sections at the low
   (output) rate, with differential delay `M`. Multiplierless (adders +
   registers only). Built as **generate chains** (one register + adder per
   stage), not a procedural unrolled loop.

4. **Compensation FIR** (`ddc_fir`): a direct-form FIR at the decimated rate
   that corrects the CIC `sin(x)/x` droop. Each tap is **generated hardware**
   (a `genvar generate` loop instantiating one multiplier per tap into a
   `products` array) followed by an **explicit running-sum reduction**, not the
   procedural `acc = acc + shift[i]*h[i]` MAC pattern. Coefficients are packed
   into a single `[NTAP*CW-1:0]` parameter `H` (Q1.15, tap `i` at
   `H[i*CW +: CW]`). The result is round-half-up and saturated to `OUTW` bits.

The CIC+FIR pair is instantiated **per lane** (I and Q) via a generate loop.

### CIC bit growth

The maximum internal register growth of an `N`-stage CIC with rate change `R`
and differential delay `M` is

```
  Bmax = ceil( N * log2(R*M) )       bits
```

so every internal CIC register is sized `IQW + Bmax`. With the defaults
(`STAGES=4`, `R=8`, `M=1`): `Bmax = ceil(4*log2(8)) = 12`, i.e. 28-bit internal
registers for `IQW=16`. The comb output is arithmetically right-shifted by
`Bmax` to renormalize the `(R*M)^N` DC gain and return a Q1.15 sample.

### Parameters

| Parameter | Default | Meaning                                         |
|-----------|---------|-------------------------------------------------|
| `DW`      | 16      | Real input width (Q1.15)                        |
| `OUTW`    | 16      | I/Q output width (Q1.15)                         |
| `IQW`     | 16      | Internal working width (Q1.15)                   |
| `PAW`     | 24      | NCO phase accumulator width                      |
| `AW`      | 8       | Sine ROM address width (`log2 NSIN`, NSIN=256)  |
| `SW`      | 16      | NCO sample width (Q1.15)                         |
| `STAGES`  | 4       | CIC integrator/comb stages (N)                  |
| `R`       | 8       | CIC decimation factor                           |
| `M`       | 1       | CIC differential delay                          |
| `CW`      | 16      | FIR coefficient width (Q1.15)                    |
| `NTAP`    | 15      | FIR taps                                         |
| `H`       | impulse | Packed `[NTAP*CW-1:0]` FIR coefficients         |

The default `H` is a unit impulse at the center tap (a pure delay); a real
deployment overrides it with droop-compensation coefficients.

### Interface

| Signal      | Dir | Width  | Meaning                                  |
|-------------|-----|--------|------------------------------------------|
| `clk`       | in  | 1      | Clock                                    |
| `rst`       | in  | 1      | Synchronous active-high reset            |
| `in_valid`  | in  | 1      | Input sample valid (asserted every Fs)   |
| `ftw`       | in  | PAW    | NCO frequency tuning word                |
| `in_data`   | in  | DW     | Real bandpass input (Q1.15)              |
| `out_valid` | out | 1      | Output strobe (once per R inputs)        |
| `iout`      | out | OUTW   | In-phase baseband output (Q1.15)         |
| `qout`      | out | OUTW   | Quadrature baseband output (Q1.15)       |

### Streaming model

Valid-only with a decimated `out_valid` strobe: `out_valid` pulses once per `R`
input samples. **NOT SUPPORTED:** ready/backpressure (no `ready` handshake),
mid-stream `ftw` reprogramming guarantees (changing `ftw` is allowed but the
old/new boundary is not specially aligned), and per-sample throttling. This
matches `blocks/fft` and `blocks/ofdm`.

## Synthesis mapping

- **NCO sine ROM**: a 256-entry combinational `case` (emitted by `genddc.py`),
  read combinationally and instantiated twice (sin + cos). It deliberately maps
  to **LUTs, not BRAM** -- FPGA block RAM is synchronous-read only and the
  `zeroasic_z1015` BRAM is `init none`, and the flow runs `--ignore-initial`, so
  a constant ROM cannot live in BRAM. Same rationale as `blocks/fft`.
- **Multipliers**: the mixer uses ~2 multiplies; the FIR uses `NTAP`
  multiplies. These map to DSP / `efpga_mult` blocks (~`2 + NTAP` ~= 17 for the
  defaults, x2 if the tool does not share between lanes -- the FIR is
  per-lane).
- **CIC and control** (phase accumulator, integrators, combs, decimation
  counter, valid pipeline): LUT/FF only, no multipliers.
- **No BRAM** is expected (the only table is the case-ROM).

## Provenance

This is an **original implementation** written for LogikBench. It follows the
architectures in the cited references (Hogenauer CIC, sine-table NCO,
compensation FIR) but is not copied from any of them. The sine ROM is generated
by `genddc.py` (deterministic table). No third-party RTL is vendored.
