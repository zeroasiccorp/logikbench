# huffman (static canonical Huffman codec)

**Source:** [rtl/huffman.v](rtl/huffman.v)

## What it is

A **static canonical Huffman codec** for 8-bit symbols: an encoder that maps
symbols to variable-length canonical codes and bit-packs them, and a decoder
that recovers the symbols from the bitstream. `huffman` (top) wires the encoder's
compressed byte stream straight into the decoder (a self-checking loopback), so
decoded symbols equal the input symbols.

## Architecture

- **`huffman_enc`** — per-symbol `{code, length}` from a baked-in canonical ROM,
  fed to a bit-packer that concatenates codes MSB-first and emits output bytes;
  `in_last` flushes the final partial byte. Streaming with valid/ready.
- **`huffman_dec`** — bit-serial *puff-style* canonical decode: per code length
  `L`, codewords occupy a contiguous range; `cnt[L]` and the symbol-order ROM
  drive the decode. Streaming: bytes in (valid/ready), symbols out (valid).
- **`huffman`** — top: `huffman_enc` -> `huffman_dec` loopback example.

## The code table

The canonical Huffman code is **static** (baked into ROMs, generated by
`genhuff.py`), so this is "table-driven" rather than a dynamic tree builder. The
table is documented inline in the RTL and summarized here:

- **256 8-bit symbols.** Code lengths come from a canonical Huffman code built
  for the frequency model `freq[s] = round(1e6 * 0.98^s)`, `s = 0..255` -- a
  geometric distribution: smaller symbol values are more frequent and so get
  shorter codes. **Max code length = 13 bits** (cap 15).
- Encoder ROM: a combinational `case` on `in_sym` drives `enc_len_r` (code
  length in bits) and `enc_code_r` (the canonical code, right-justified; the
  low `enc_len_r` bits are emitted MSB-first).
- Decoder ROMs: a `case` on `len` drives `cnt_r` (number of codewords of that
  length) and a `case` on the canonical symbol index drives `dsym_r` (the
  symbol in canonical order, sorted by code length then symbol value). These
  plus the canonical first-code recurrence are all the decoder needs. The
  tables are plain combinational `case` ROMs (no Verilog functions).
- Regenerate / change the distribution (or cap) with `python genhuff.py` (then
  reindent with emacs verilog-mode). The generator checks the Kraft equality and
  that the max length stays within the cap.

## Interface

| Signal      | Dir | Width | Meaning                                  |
|-------------|-----|-------|------------------------------------------|
| `clk`       | in  | 1     | clock                                    |
| `rst`       | in  | 1     | synchronous, active high                 |
| `in_valid`  | in  | 1     | input symbol valid                       |
| `in_sym`    | in  | 8     | input symbol                             |
| `in_last`   | in  | 1     | last symbol of the frame (flush)         |
| `in_ready`  | out | 1     | codec can accept a symbol                |
| `out_valid` | out | 1     | recovered symbol valid                   |
| `out_sym`   | out | 8     | recovered symbol                         |

## Mapping

ROMs (code/length, count, symbol order) -> LUTs; bit-packer (barrel shift +
accumulator) and bit-serial decoder -> LUTs + FFs. No DSP, no BRAM.

## Files

- `rtl/huffman_enc.v`, `rtl/huffman_dec.v` -- encoder / decoder (generated by
  `genhuff.py`, which emits the documented table ROMs).
- `rtl/huffman.v` -- top loopback codec.
- `genhuff.py` -- regenerates the enc/dec (table ROMs) from the frequency model.
- `testbench/test_huffman_smoke.v` -- Verilog-2005 self-checking round-trip
  (random symbols -> enc -> dec -> compare). Run:

  ```
  iverilog -g2005 -o sim.out rtl/huffman_enc.v rtl/huffman_dec.v rtl/huffman.v \
           testbench/test_huffman_smoke.v
  vvp sim.out
  ```
